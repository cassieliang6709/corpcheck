Technical route

从 SEC 原文到可审计证据

CorpCheck 的核心不是 prompt，而是一条可复现的检索链路。每一步都能回到源码、数据库字段和离线评测。

  1. 01

    Ingest

    下载并识别 SEC filing

    从 EDGAR 获取 10-K / 10-Q，保留 ticker、CIK、accession number、提交日期和财年。

  2. 02

    Represent

    按章节与表格重建文本

    清理 HTML，同时保留 section、table 与 provenance；SEC narrative 目标 420 tokens / 60 overlap，table 为 320 tokens / 3-row overlap。

  3. 03

    Encode + index

    384 维向量与全文索引并存

    all-MiniLM-L6-v2 生成归一化 embedding；PostgreSQL 同时维护 pgvector cosine 与 ts_rank。

  4. 04

    Retrieve

    理解查询，再融合两路候选

    先解析公司、文件类型与财年；dense + sparse 各自召回后，以 RRF 融合，并过滤被 amendment 替换的 section。

  5. 05

    Gate

    用原始 cosine 决定是否拒答

    Top-1 需 ≥ 0.42，mean top-3 需 ≥ 0.40。门槛读取未加 boost 的相似度，避免排序分数伪装成置信度。

  6. 06

    Serve + evaluate

    HTTP、MCP 与评测共用 retrieve()

    网页、agent 和离线 FinanceBench 不各写一套检索；生成层只有在证据 gate 通过后才有资格被调用。

设计约束

同一个问题必须能沿着 输入 → 候选 → 融合 → 版本治理 → 门槛 → 来源 逐层解释；否则就不是审计级答案。

Claim verification layer

同一套证据，第二个用途

检索层回答「有没有证据」；claim 层回答「这句话是不是真的」。两者共用同一个 retrieve()、同一份语料、同一套 provenance 规则——它不是另一个项目，是同一个内核的第二个接口。判定过程不调用 LLM。

01 · 输入一句新闻

「Apple repurchased $3.7 billion of its common stock during the second quarter of fiscal 2023.」

02 · 拆成结构化 claim

  • metric share_repurchase
  • period FY2023Q2
  • value $3.7B
  • as_of day-granular

03 · 在 10-Q 原文中绑定数值

The Company repurchased $19.1 billion of its common stock and paid dividends and dividend equivalents of $3.7 billion during the period.

REFUTED

$3.7B 绑定的是 dividend，不是 share_repurchase。回购的真实数字是 $19.1B，与声明不符。

这条案例是回归测试，因为第一版把它判成了 verified。当时的实现只检查「这个数字有没有出现在检索到的文本里」，指标和财年从未被提取——同一句话里的分红金额足以为一条关于回购的声明背书。对一个以核查金融声明为目的的系统，误判为真比查不出来更严重。现在数值必须绑定到它前面出现的指标名，指标识别不出时直接 fail closed。

Verdict含义
verified指标、期间、数值三者都与检索到的证据绑定一致
refuted指标与期间已绑定，数值不符
conflicting范围内的证据自相矛盾
insufficient_evidence范围内没有任何证据能绑定到该指标
not_yet_decidable预测类声明，证据尚不存在
non_verifiable观点或不可证伪的表述

当前边界：claim 层通过 POST /claims/extract 与 POST /claims/verify 提供，运行在本地 API 上。本页是静态页面，没有后端，无法在线试用。8 个对抗回归用例覆盖了指标误绑、变化量、股数与金额混淆、四舍五入和时点截止；证据「选择」仍弱于证据「绑定」，遗留缺陷记录在 docs/CLAIMS_DEMO.md。

为什么不是普通 RAG

三个可以被验证的产品承诺

01

用评测约束检索

线上 API 与离线 FinanceBench 评测共用同一个 retrieve()。当前 strict Recall@10 基线只有 0.1429，因此生成能力继续关闭，而不是把低质量结果包装成产品准确率。

02

每条证据可追溯

网页结果保留 ticker、10-K/10-Q、财年、提交日期与 SEC 原始链接；MCP 的 filing context 还会返回 accession number。

03

拒答发生在 LLM 之前

top-1 cosine 需达到 0.42，mean top-3 需达到 0.40。任何一个门槛未通过，都不会把弱证据交给生成模型。
